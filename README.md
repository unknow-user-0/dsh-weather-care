# dsh-weather-care · 天气关怀

让 DSH 里的伙伴**自己知道外面什么天**，不用你问。

## 它做的三件事

1. **每轮都带一行天气。** 每次开口前，上下文末尾就有「现在 X°C、今天 X~X°C、未来几小时……」这一行，不用调工具就能接上话（「外面有点凉，多穿件」）。
2. **`weather` 工具。** 想看更细的——几点开始下雨、明天要不要带伞、这周哪天晴——让它查，返回逐小时 + 多日，中文文本直接照着说。
3. **自己开口说几句**（私聊，像聊天，不像播报）。
   - 早报：到点（默认 07:30）说一句今天的天气要点；**开机晚了也补一条**（「晚开机补发」默认 240 分钟，控制台里可改）；
   - 晚间预告：前一天晚上提一句明天要不要带伞、冷不冷；
   - 突变提醒：气温骤降、要下雨/下雪、风变大时提一嘴（同类 3 小时只说一次，一天最多 4 次，夜里静默）。
   - 文案不是固定模板：用宿主默认模型现写一句（每次换切入点——有时先聊两句再说天气，有时只说最要紧的一句），模型不可用时退回随机句式兜底。

## 控制台页面（改设置不用编辑 JSON）

两个入口，同一套设置：

- **GUI 里**：左栏多一个天气图标（`sidebar.panellist`，id `weather`），点开右边主面板就是天气台（`main`，key `weather`）。要显示它得**刷新一次页面**（新加的客户端模块是页面加载时才注册的）。
- **浏览器里**：`http://<当前 DSH Web 地址>/dsh-weather/`（DSH 每次启动端口会变，以运行时上下文里那个 `http://127.0.0.1:端口` 为准，后面拼 `/dsh-weather/`），独立页面，不占会话。面板改完立刻生效，不用重载插件。

能改：播报城市、早报时间与「晚开机补发」、前一天晚上的明日预告、同类提醒间隔与每天上限、静默时段、播报带不带日出日落、QQ 总开关；推送对象列表里还能给每个人单独设 位置 / 早报开关与时间 / 晚报开关与时间 / 突变提醒开关。还有「重新定位」「预览播报文案」「发条测试」三个按钮。

## 每个人自己发指令改设置

对方在 QQ 私聊里发 `*/帮助` 就能看到全部指令（第一次私聊时也会自动发一份说明书）：

| 指令 | 作用 |
| --- | --- |
| `*/位置 杭州` | 设成自己所在的城市（不填就是查现在设了哪） |
| `*/早报 07:30` / `*/早报 关` | 早报时间 / 开关 |
| `*/晚报 21:00` / `*/晚报 关` | 晚间预告时间 / 开关 |
| `*/突变 开` / `*/突变 关` | 天气突变要不要提醒 |
| `*/状态` | 看现在的设置 |
| `*/帮助` | 再看一遍说明书 |

默认值来自控制台的全局设置；对端单独设过的就按对端的来。群聊已经不再支持，只做私聊。

## 主动消息发到哪

默认走 **QQ**（你在手机上收得到），发不出去就退回本机叫醒。

| 配置项 | 说明 |
| --- | --- |
| `qqOn` | 总开关，默认 `true` |
| `qqUsers` | 推给哪些好友（号码数组），控制台里多选；只发私聊，群聊已去掉 |
| `qqTarget` | 旧字段：单个 QQ 号或群号；留空就用桥配置里的 |
| `qqConfigFile` | 一份自家桥的 `config.json`，从里面读 `snowluma.httpUrl` / `snowluma.accessToken` / `ownerQQ` |
| `qqNapcat` `qqToken` | 直接指定 OneBot HTTP 地址与 access_token（优先级最高） |
| `qqAlsoFollowup` | 发了 QQ 之后，本地要不要也醒一次，默认 `false` |

也可以放 `~/.dsh/weather-plugin.json`（JSON，键名同上），优先级低于 `cordis.patch.yml` 里的 `config`。

「推给哪些 QQ」的选人列表只列出**已经接进 DSH 会话、并且那个会话没被归档**的对象：标题形如 `QQ好友 · 123456789`（号码）或 `QQ好友 · 杏一枚`（昵称）的会话算「已接通」，`~/.dsh/storages/workspace.json` 里 `global.archivedSessionIds` 里的算「已归档」、会被排除。

## 其他可调项

```json
{
  "place": "",
  "briefEnabled": true,
  "briefTime": "07:30",
  "briefWindowMin": 120,
  "eveningOn": false,
  "eveningTime": "21:00",
  "eveningWindowMin": 120,
  "sunOn": true,
  "alertsEnabled": true,
  "quietFrom": "23:00",
  "quietTo": "07:00",
  "minAlertGapMin": 45,
  "sameKindGapMin": 180,
  "maxAlertsPerDay": 4
}
```

- `place` 留空 = 按 IP 自动定位（换城市不用改）；填「上海」这种中文城市名就固定在那儿。
- `briefWindowMin`：过了早报时间这么久之内还补发（开机晚了也能收到），再晚就不补了，免得半夜重载插件突然来句早安。
- `eveningOn`：前一天晚上（默认 21:00）先说一遍明天，顺带提「比今天低几度，记得添衣」。
- `sunOn`：播报和早报里带不带「日出 06:31、日落 17:19」。
- `sameKindGapMin`：同一类提醒（比如连着几小时的降雨）至少隔多久才再说一次；`minAlertGapMin` 是任意两次提醒的间隔；`maxAlertsPerDay` 是每天上限。
- 静默时段内不主动说话（早报也不会在半夜补发）。

### 定位会飘的话

自动定位会同时问 **ipip.net / ipwho.is / ipapi.co** 三家，拿到城市名候选后交给 Open-Meteo 地理编码换成精确经纬度和中文名（ipip 排第一，国内最准）。IP 定位终究只看出口 IP，挂 VPN / 多线路时仍可能一天里换城市，所以插件会把结果**记到 `~/.dsh/weather-plugin-state.json`**，12 小时内沿用同一个城市。想彻底钉死就在控制台填城市名（或 `{ "place": "北京" }`）。

### 每个人自己发指令改设置

天气台**只发私聊**，群聊已经去掉。每个私聊对象的位置、早报、晚报、突变都可以由对方自己在 QQ 里发消息改，指令以 `*/` 开头：

| 指令 | 作用 |
| --- | --- |
| `*/位置 杭州` | 设定自己在哪个城市（走地理编码存坐标）；只发 `*/位置` 是查看 |
| `*/早报 07:30` | 早报时间；`*/早报 开` / `*/早报 关` 开关 |
| `*/晚报 21:00` | 晚上预告明天的时间；`*/晚报 关` 关掉 |
| `*/突变 开` / `*/突变 关` | 天气突变提醒要不要 |
| `*/状态` | 看自己现在的设置和今天已经收到的次数 |
| `*/帮助` | 再看一遍全部指令 |

- 插件每分钟读一次各对象的私聊历史（`get_friend_msg_history`，只认对方发来的新消息），认出指令就照做并回一句确认；
- **第一次接入**（对方第一次私聊）会自动发一遍指令说明书，只发这一次；
- 对方的城市存在 `~/.dsh/weather-plugin-peers.json`，早报/晚报/突变也一起记在这儿；控制台的「每个人的设置」里能看能改，效果和发指令一样；
- 没设过城市的人照样用本机定位播报；**突变预警**也按各自城市判断。

## 不对劲时先自检

调 `weather` 时带 `status: true`，它会告诉你：定位到哪、天气快照多新、早报今天播没播、QQ 发到哪个号哪个地址、桥配置读没读到、心跳跳了几次。

```
定位：北京（自动）　天气快照：07:31 更新
定位依据：2 家 IP 库响应，取「北京」
早报：07:30（今天已播）
晚间预告：21:30（今晚还没播）
突变预警：1/4 次（同类至少隔 240 分钟，两次至少隔 45 分钟）
静默：23:00~07:00　日出日落：带
QQ：开 → 私聊 123456789 @ http://127.0.0.1:3000（令牌已配）
桥配置文件：…/qqbridge/config.json（已读到）
心跳（每 60 秒一次）：37 次，07:58 最后一次
```

## 数据从哪来

两种天气源，二选一：

- 没填彩云令牌（默认）：[Open-Meteo](https://open-meteo.com/)，免费、不要密钥；
- 在面板「天气数据」里填了[彩云天气](https://docs.caiyunapp.com/)的 token：自动改走彩云，Open-Meteo 只在彩云出错时兜底。

定位用 [ipip.net](https://myip.ipip.net/) / [ipwho.is](https://ipwho.is/) / [ipapi.co](https://ipapi.co/) 三家 IP 库交叉验证，城市名解析用 Open-Meteo 地理编码。都是 HTTPS 公网请求，只发经纬度或城市名，不带本机其他信息。

**边界**：网络不通就降级成「这一轮没有天气」，绝不打断对话；QQ 发不出去也只写一条日志，消息退回本机。

## 不想要什么就关什么

- 只要「能查天气」：`qqOn: false`、`briefEnabled: false`、`alertsEnabled: false`
- 只要早报不要突变：`alertsEnabled: false`
- 不想它主动开口：两个都 `false`，`weather` 工具和每轮那行天气都还在

## 安全与隐私

装之前值得知道它碰了什么：

**读**（只读，且都带容错，读不到就当没有）
- `~/.dsh/storages/session_projcache/sessions/*.json` 里的会话标题 —— 用来认出「QQ好友 · 123456789」这种会话，好把推送对象跟人对应起来；
- `~/.dsh/storages/workspace.json` 里的 `global.archivedSessionIds` —— 归档掉的会话不再出现在选择列表里；
- 自家 QQ 桥的 `config.json`（如果配了 `qqConfigFile`）—— 取 OneBot 地址、access_token、默认收件人。

**写**（都在 `~/.dsh/` 下，纯 JSON）
- `weather-plugin.json`：面板里改的设置（**彩云 token 就明文存在这里**，文件权限跟随系统默认）；
- `weather-plugin-state.json`、`weather-plugin-peers.json`：快照、每个人设的城市和时间。

**发**
- 天气/定位请求发往 Open-Meteo、彩云、ipip.net、ipwho.is、ipapi.co；
- QQ 消息只发到你自己配的 OneBot（默认本机 `127.0.0.1`），不发第三方。

**本地接口**
`/dsh-weather/api/*` 挂在 DSH 自己的 loopback 上，没有账号体系。带了一道简单校验：跨站来源（`Sec-Fetch-Site: cross-site` 或 http(s) Origin 与 Host 不一致）直接 403，桌面客户端的 `dsh-app://` 协议放行。也就是说**同一台机器上的其它进程仍然能读**推送对象的 QQ 号和城市、也能改设置 —— 单机工具默认信任本机，介意的话可以用防火墙/进程隔离限制本机访问。

**不会发生的事**
没有 `eval`/`new Function`/`child_process`，不加载任何远端代码，不静默升级；报错信息里出现彩云 token 会被打码成 `***`。
